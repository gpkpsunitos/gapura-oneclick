# Gapura IRRS2 Codebase Exploration Plan

## Executive Summary

This document provides a comprehensive exploration of the Gapura IRRS (Irregularity Reporting & Resolution System) Dashboard codebase, a full-stack operational monitoring and reporting system for Gapura Angkasa, an aviation ground handling company.

---

## 1. Project Overview

**Name:** Gapura OneClick IRRS Dashboard
**Type:** Web-based operational reporting and analytics platform
**Primary Purpose:** Track, monitor, and analyze irregularities, complaints, and incidents across airport operations

### Core Functionality
- Report submission and tracking of operational incidents
- Role-based access control (RBAC) for different user types
- AI-powered analytics and insights
- Real-time dashboards with drill-down capabilities
- Document and evidence management
- Integration with Google Sheets and Supabase

---

## 3. Architecture

### 3.1 High-Level Architecture

```
┌─────────────────┐
│   User Browser  │
│   (React UI)    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  Next.js Proxy  │
│  (Middleware)   │
└────────┬────────┘
         │
         ▼
┌─────────────────────────────────────┐
│       Next.js App Router           │
│  ┌──────────┬──────────┬─────────┐ │
│  │  Pages   │   API    │ Actions │ │
│  └──────────┴──────────┴─────────┘ │
└────────┬──────────────────────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌─────────┐ ┌──────────────┐
│Supabase│ │Google Sheets │
│ (DB)    │ │ (Reports)    │
└─────────┘ └──────────────┘
```

### 3.2 Data Flow

1. **Report Data Pipeline:**
   - Google Sheets (NON CARGO, CGO tabs) → `reports-service.ts` → Normalization → Cache → API → UI
   - Each row mapped to canonical Report object with UUID v5 ID
   - Cache at multiple levels (in-memory, filesystem)

2. **Authentication Flow:**
   - Login → `/api/auth/login` → Validate with Supabase → Create JWT → Set cookie
   - Middleware (`proxy.ts`) validates session on protected routes
   - Redirects users to role-specific dashboards

3. **AI Integration:**
   - External AI service: https://gapura-dev-gapura-ai.hf.space
   - GROQ API for queries
   - Cached responses for performance

## 6. Core Services & Algorithms

### 6.1 Reports Service (`lib/services/reports-service.ts`)

**Purpose:** Core service for reading, normalizing, and serving report data

**Key Functions:**
- `getAllReports()`: Fetch all reports from Sheets + Supabase
- `mapRowToReport()`: Convert Google Sheets row to Report object
- `generateCanonicalId()`: Create UUID v5 from sheet!row reference
- `getReportsByStation()`: RBAC-filtered station reports
- `invalidateCache()`: Clear all cache layers

**Cache Strategy:**
- In-memory TTL cache (100 entries max)
- Filesystem cache (`/tmp/gapura-irrs-cache`)
- Configurable TTL per operation

**Data Normalization:**
- Header mapping (multiple possible header names)
- Status normalization
- Category mapping
- Station/Branch code extraction
- Date parsing

### 6.2 Authentication (`lib/auth-utils.ts`)

**Functions:**
- `hashPassword()`: bcrypt password hashing
- `verifyPassword()`: bcrypt password verification
- `signSession()`: JWT token creation (24h expiry)
- `verifySession()`: JWT validation + session DB check

**Session Management:**
- Session ID (SID) tracking in database
- Session revocation support
- Last active timestamp updates
- 15-minute activity check

### 6.3 Google Sheets Integration (`lib/google-sheets.ts`)

**Key Operations:**
- Sheet authentication via service account
- Batch row reading
- Sheet metadata retrieval
- Dynamic column detection

**Supported Sheets:**
- NON CARGO (primary report sheet)
- CGO (cargo reports)

### 6.4 AI Integration (`lib/services/gapura-ai.ts`)

**Features:**
- Groq API client for LLM queries
- OpenAI integration for advanced AI
- Cached AI responses
- Batch processing support

**Endpoints Accessed:**
- Dashboard summary generation

- Root cause analysis
